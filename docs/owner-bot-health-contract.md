# قرارداد مرکز سلامت Kronos Guard

## دامنه و دسترسی

این مرکز فقط برای مالک رسمی Kronos Guard در دسترس است. داده‌ها از endpoint عمومی health جدا هستند و هر درخواست باید از جلسهٔ امضاشدهٔ Mini App عبور کند؛ سپس شناسهٔ تلگرام بازیگر باید با شناسهٔ مالک پیکربندی‌شده برابر باشد. هیچ آمار عملیاتی یا پیام خطای داخلی نباید در پاسخ‌های کاربران عادی دیده شود.

## داده‌های سطح اول

| حوزه | منبع موجود | خروجی ایمن برای مالک |
|---|---|---|
| آماده‌بودن ربات | نمونهٔ Telegraf در حافظه | وضعیت آماده/در دسترس‌نبودن، بدون افشای token |
| اتصال API تلگرام | `getMe` و زمان اجرای آن | وضعیت، شناسهٔ عددی و نام کاربری ربات در صورت موفقیت، و تأخیر برحسب میلی‌ثانیه |
| وبهوک | `getWebhookInfo` | فعال‌بودن URL، تعداد updateهای معوق و زمان آخرین خطای API؛ بدون افشای URL حساس |
| پردازش رویداد | جدول `webhookEvents` | تعداد رویدادهای دریافت‌شده، پردازش‌شده، ناموفق و آخرین زمان دریافت در بازهٔ 24 ساعت |
| صف عملیاتی | جدول `scheduledJobs` | شمار pending/running/failed و قدیمی‌ترین اجرای معوق |
| کش متادیتای گروه | `getGroupChatMetadataCacheMetrics` | hit، miss، hit rate و entry count |
| دادهٔ پایدار | اتصال دیتابیس | وضعیت قابل‌دسترس/غیرقابل‌دسترس و زمان اجرای بررسی، بدون اطلاعات اتصال |

## قواعد وضعیت

| سطح | معیار |
|---|---|
| `healthy` | دیتابیس و Bot API پاسخ می‌دهند، وبهوک خطای اخیر ندارد و صف شکست‌خورده‌ای وجود ندارد. |
| `degraded` | سرویس اصلی در دسترس است اما backlog وبهوک، خطای اخیر، صف شکست‌خورده یا تأخیر بالا نیازمند توجه است. |
| `unavailable` | نمونهٔ ربات، دیتابیس یا API تلگرام برای snapshot قابل‌دسترسی نیست. |

## حریم داده و رفتار خطا

هر بخش snapshot مستقل محاسبه می‌شود تا نقص یک منبع، بقیهٔ داده‌ها را پنهان نکند. خطاها به برچسب عملیاتی کوتاه تبدیل می‌شوند و stack trace، token، webhook URL کامل، متن پیام‌های کاربران و جزئیات اتصال پایگاه داده هرگز برگردانده نمی‌شوند. این endpoint صرفاً خواندنی است و هیچ تغییر عملیاتی ایجاد نمی‌کند.
