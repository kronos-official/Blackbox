# گزارش تحویل اصلاح native picker استخراج آیدی

## دامنهٔ تغییر

فلو استخراج آیدی عددی Kronos Guard اکنون به‌جای فهرست داخلی و اسکن‌شده، از چهار دکمهٔ رسمی Telegram در کیبورد پاسخ استفاده می‌کند: «انتخاب کاربر از Telegram»، «انتخاب ربات از Telegram»، «انتخاب گروه از Telegram» و «انتخاب کانال از Telegram». دکمه‌ها با `KeyboardButtonRequestUsers` و `KeyboardButtonRequestChat` ساخته می‌شوند و چهار شناسهٔ درخواست ثابت برای اتصال امن انتخاب به مرحلهٔ جاری دارند.

## فلو نهایی

کاربر ابتدا «استخراج آیدی» را از کیبورد اصلی انتخاب می‌کند، سپس دستهٔ مقصد را می‌زند. ربات یک کیبورد native رسمی Telegram می‌فرستد؛ پنجرهٔ انتخاب توسط خود Telegram باز می‌شود و ربات هیچ فهرست سفارشی، ورود دستی username یا ورود دستی لینک ارائه نمی‌کند. پس از انتخاب، پیام `users_shared` یا `chat_shared` دریافت می‌شود، مقصد در یک مرحلهٔ تأیید نمایش داده می‌شود و با انتخاب «ارسال»، شناسهٔ عددی واقعی از `getChat` یا دفترچهٔ معتبر Telegram resolve شده و کارت Kronos Guard ارسال می‌شود.

## فایل‌های اصلی

| فایل | تغییر |
|---|---|
| `server/telegram/persistentKeyboard.ts` | افزودن چهار native request button، شناسه‌های درخواست و کیبورد یک‌بارمصرف انتخاب مقصد |
| `server/telegram/numericIdConversion.ts` | حذف مسیر فهرست داخلی، پردازش `users_shared` و `chat_shared`، حفظ تأیید و کارت نهایی |
| `server/telegram/bot.ts` | اتصال پیام‌های native shared به dispatcher پیش از مسیرهای عمومی پیام |
| `server/telegram/persistentKeyboard.test.ts` | regression برای هر چهار request button و شناسهٔ درخواست |
| `server/telegram/numericIdConversion.test.ts` | regression برای مسیر واقعی Category → native shared → Confirmation |
| `notes/telegram-native-picker-research.md` | مستند محدودیت‌ها و قابلیت‌های رسمی Telegram |

## کنترل کیفیت

تعداد **۷۰ فایل تست و ۲۷۷ تست** با موفقیت اجرا شد. بررسی TypeScript بدون خطا انجام شد و build تولیدی Vite و esbuild نیز موفق بود. هشدارهای موجود صرفاً هشدارهای وابستگی pnpm و اندازهٔ chunk هستند و مانع build یا اجرای سرویس نیستند.

## نکتهٔ آزمون زنده

اجرای پنجرهٔ native picker وابسته به کلاینت Telegram است و باید در یک نشست واقعی Telegram Web یا Telegram Desktop با حساب مالک انجام شود. تست‌های خودکار، ساخت دقیق payload، اتصال dispatcher و دریافت هر دو نوع shared update را پوشش می‌دهند؛ تأیید بصری باز شدن پنجره و انتخاب مقصد در کلاینت واقعی، آخرین مرحلهٔ پذیرش عملیاتی است.

## شاهد پذیرش زندهٔ native picker

در نشست واقعی Telegram Web، مسیر «استخراج آیدی → کاربران» اجرا شد. پنجرهٔ رسمی **Choose Users** خود Telegram باز شد، حساب آزمایشی `s` انتخاب گردید، پیام `users_shared` به ربات رسید، مرحلهٔ تأیید با دکمه‌های «ارسال» و «انصراف» نمایش داده شد و پس از تأیید، کارت نهایی با شناسهٔ عددی `8049486168` و نام کاربری `@OrewaSara` ارسال شد. این شاهد، اتصال واقعی Category → native picker → shared update → Confirmation → Numeric ID Card را تأیید می‌کند.

این آزمون برای دستهٔ کاربران انجام شد؛ رفتار سه دستهٔ دیگر با regressionهای مستقل و payloadهای رسمی پوشش داده شده است. دو مورد مربوط به پذیرش زندهٔ جداگانهٔ «نمایش لینک به صورت عکس» عمداً باز باقی مانده‌اند و در این گزارش به‌عنوان آزمون انجام‌شده ادعا نمی‌شوند.

## وضعیت تحویل

کد برای چهار دستهٔ کاربران، ربات‌ها، گروه‌ها و کانال‌ها آماده است. مسیرهای manual username/link و فهرست داخلی غیرفعال شده‌اند و مرحلهٔ تأیید و کارت شناسهٔ عددی حفظ شده است.

### شاهد تکمیلی آزمون زندهٔ مرکز لینک
در نشست Telegram Web و گروه آزمایشی `@anonymousgapsecret`، مرکز لینک با دکمهٔ «نمایش لینک به‌صورت کارت تصویری» مشاهده شد. دکمهٔ آخرین پیام مرکز لینک با متن دقیق «• نمایش لینک به‌صورت کارت تصویری» اجرا شد؛ پس از بررسی چند پیام آخر و DOM، پیام تصویری جدید یا caption کارت لینک قابل مشاهده نبود. بنابراین این پذیرش زنده **ناموفق/تأییدنشده** ثبت می‌شود و موفقیت برای آن ادعا نمی‌شود. آزمون native picker جداگانه موفق بود و کارت نهایی شناسهٔ عددی گروه `-1003795743979` در Telegram Web مشاهده شد.

## اصلاحات پس از گزارش کاربر — ۲۰۲۶-۰۸-۱۶

پس از پذیرش اولیه مشخص شد که در بعضی انتخاب‌ها، Telegram شناسهٔ عددی را برمی‌گرداند اما دریافت metadata تکمیلی از Bot API موفق نیست؛ در نتیجه نسخهٔ قبلی به‌اشتباه پیام نبود اطلاعات مقصد را نمایش می‌داد. مسیر جدید آیدی معتبر موجود در `users_shared` یا `chat_shared` را مستقل از metadata حفظ می‌کند و در صورت نبود نام، توضیحات یا عکس، کارت نهایی را با همان شناسهٔ عددی و متن شفافِ نبود اطلاعات تکمیلی ارسال می‌کند.

دکمهٔ «لغو عملیات» نیز به‌دلیل reply keyboard بودن، callback نبود و در dispatcher قبلی پردازش نمی‌شد. اکنون پیام متنی آن شناسایی می‌شود، state موقت کاربر پاک می‌گردد و فلو به دسته‌بندی اصلی استخراج آیدی بازمی‌گردد. برای هر دو اصلاح، regression اضافه شد. quality gate نهایی شامل ۷۰ فایل تست و ۲۷۹ تست موفق، TypeScript بدون خطا و build تولیدی موفق است.
